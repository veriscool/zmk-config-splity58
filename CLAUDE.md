# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Repository purpose

This is a **ZMK firmware user config repo** for `splity58` — a custom split keyboard shield based on the Lily58 layout, wired with a matrix + direct-GPIO (thumb keys) composite kscan. There is no source build tooling here (no CMake/west installed locally); this repo only holds the config/overlay files that get consumed by the ZMK build system, normally via GitHub Actions.

## Build

There is no local build. Firmware is compiled by GitHub Actions:

1. Push changes to the repo (or trigger manually).
2. Go to the **Actions** tab → **Build ZMK firmware** workflow → **Run workflow** for the first build; subsequent builds trigger automatically on push.
3. Download the compiled `.uf2` artifacts from the completed workflow run.

`build.yaml` drives the GitHub Actions build matrix (which board+shield+snippet combos get built). It currently builds:
- `central_dongle` + `snake_adapter` shields (dongle role, with ZMK Studio snippet)
- `splity58_left` (peripheral, `ZMK_SPLIT_ROLE_CENTRAL=n`)
- `splity58_right` (peripheral, `ZMK_SPLIT_ROLE_CENTRAL=n`)
- `settings_reset`

The commented-out block shows how to add a `splity58_left`-with-studio variant if needed.

There are no tests or linters in this repo — changes are validated by whether the Actions build succeeds and by flashing/trying the firmware on hardware.

## Module dependencies (`config/west.yml`)

This config pulls in ZMK plus two third-party modules via west manifest imports:
- `zmk-rgbled-widget` (caksoylar) — RGB LED status widget (`CONFIG_RGBLED_WIDGET`)
- `snake-module` (joaopedropio) — adds a Snake game / custom OLED display screen and its extensive theming Kconfig (see below)

If display/RGB/snake behavior seems missing or misbehaving, check whether it lives in one of these external modules rather than in this repo.

## Architecture: three shields, one physical layout

The keyboard has **three distinct build targets** sharing one physical key layout, distinguished by `boards/shields/splity58/Kconfig.shield`:

- **`splity58_left`** — left half, peripheral role. Overlay: `splity58_left.overlay`.
- **`splity58_right`** — right half, peripheral role. Overlay: `splity58_right.overlay`. Applies `&matrix_transform0 { col-offset = <6>; }` to shift its columns into the second half of the combined matrix.
- **`central_dongle`** — a separate dongle device (not one of the physical keyboard halves) that acts as the BLE central and hosts the display/Studio/Snake features. Overlay: `central_dongle.overlay`, uses a `zmk,kscan-mock` (it has no physical keys of its own) plus `matrix_transform0` and the physical layout purely to satisfy ZMK's requirement for a layout/kscan on the central.

Shared definitions:
- **`splity58.dtsi`** — defines `matrix_transform0` (the RC(row,col) → key-position map used by the *keyboard halves*), the rotary encoder (`left_encoder`, disabled by default, enabled only in `splity58_left.overlay`), status LEDs, and wires `physical_layout_splity58.transform`.
- **`splity58-layouts.dtsi`** — defines `physical_layout_splity58`, the physical key geometry (position/rotation) shared across all three shields/overlays.
- Each half's overlay defines its own **kscan_composite** combining a `kscan-gpio-matrix` (main keys) and a `kscan-gpio-direct` (thumb cluster keys, offset via `row-offset` so positions don't collide with the matrix rows).

When changing key wiring/pinout, edit the relevant `*_left.overlay` / `*_right.overlay` kscan blocks. When changing key *positions/geometry*, edit `splity58-layouts.dtsi`. When changing the row/column-to-keymap-position mapping, edit `matrix_transform0` in `splity58.dtsi` (halves) or `central_dongle.overlay` (dongle, must stay consistent with the halves).

## Keymap (`config/splity58.keymap`)

Standard ZMK keymap with three layers: `default_layer` (base), `layer_1` ("upper", toggled via `&tog 1`), `layer_2` ("lower", toggled via `&tog 2`). Notable non-default bindings: mouse move/click/scroll (`mmv`, `mkp`, `msc`), `&ind_con`/`&ind_bat` (RGB LED indicator behaviors from the rgbled-widget module), `&studio_unlock` (ZMK Studio), and an encoder sensor binding for volume.

The repo README also references editing the keymap visually via https://nickcoutsos.github.io/keymap-editor/, and `config/splity58.json` is the physical-layout/keymap-editor metadata (generated by ZMK's Shield Wizard) — keep it in sync if you manually restructure the physical layout in `splity58-layouts.dtsi`.

## Feature configuration (`config/splity58.conf`, `boards/shields/splity58/central_dongle.conf`)

`config/splity58.conf` is the main Kconfig overlay applied to all shields and is where most feature flags live: BLE (`CONFIG_BT_MAX_CONN`/`MAX_PAIRED=7`, dongle peripheral count via `CONFIG_ZMK_SPLIT_BLE_CENTRAL_PERIPHERALS`), pointing device support, ZMK Studio, the ST7789V display driver, debounce timing, and a large block of Snake-module theming/color/sound Kconfig options (`CONFIG_SNAKE_*`, `CONFIG_THEME_*`, `CONFIG_*_COLOR`, `CONFIG_USE_*_SOUND`, `CONFIG_INFO_SLOT_*`). These color/theme options are specific to the third-party snake-module display and only take effect on the `central_dongle` build (which is the shield that owns the display, per `Kconfig.defconfig`'s `if SHIELD_CENTRAL_DONGLE` block).

`central_dongle.conf` layers dongle-specific additions on top (RGB widget, deep sleep, BT TX power).

`boards/shields/splity58/Kconfig.defconfig` sets the keyboard name, forces central role + custom display screen for `SHIELD_CENTRAL_DONGLE`, and forces `CONFIG_ZMK_SPLIT=y` for any of the three shields.
